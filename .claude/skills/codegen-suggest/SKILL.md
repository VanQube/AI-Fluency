# Codegen suggestion (Section 4.8's "bonus points" skill)

This project has one hard rule about the frontend/backend type boundary: **no
hand-written fetch calls, no hand-written TypeScript types.** Everything the
frontend uses from `frontend/src/api/generated/secureship.ts` is generated by
Orval from the backend's live `/openapi.json`. That schema comes straight
from the Pydantic models in `backend/schemas/`, the SQLAlchemy models in
`backend/models/` (via `response_model=...`/`from_attributes`), and the
routes in `backend/routes/` that wire them together.

The failure mode this skill exists to prevent: a backend route or schema
changes, nobody remembers to regenerate, and the frontend keeps compiling
against stale generated types — no compiler error, just a silent drift until
something breaks at runtime. This is a **suggestion-only** skill, per the
program's "AI assists, team reviews" principle (Section 7.2) — it must never
regenerate and overwrite frontend files on its own.

## When to act

Trigger this yourself, without being asked, immediately after you (Claude)
finish a turn where you created or edited any file matching:

- `backend/routes/*.py`
- `backend/schemas/*.py`
- `backend/models/*.py` (only relevant if the change affects a field a
  `response_model` exposes — e.g. adding/removing/renaming a column that
  flows into a `CustomerRead`/`ShipmentRead`/etc. schema)

Also run it if the user explicitly asks ("did I need to regenerate the API
client?", "check if the frontend types are stale").

## What to do

1. **Identify what changed.** `git diff` (or `git status` if uncommitted) on
   the paths above, scoped to this session's edits. Look specifically for:
   new/removed/renamed routes (`@router.get/post/put/delete(...)`, especially
   the `operation_id=` value — that's what becomes the generated hook name,
   e.g. `operation_id="listCustomers"` → `useListCustomers`), and new/removed/
   renamed/retyped fields on any `*Create`/`*Update`/*Read` schema.

2. **Check whether generated output already caught up.** Look at
   `frontend/src/api/generated/secureship.ts` — specifically whether it
   already references the new operation ID(s) or field(s) from step 1. If it
   already has them, the regeneration already happened (or isn't needed);
   say so briefly and stop, don't ask again.

3. **Summarize the delta in plain language**, e.g.:
   > Backend change: added `PATCH /admin/customers/{id}/notes` (operation_id
   > `updateCustomerNotes`) and a new `notes: Optional[str]` field on
   > `CustomerRead`. The frontend's generated hooks don't have either yet.

4. **Ask, don't act.** A single yes/no question: "Regenerate the frontend API
   client now (`npm run generate:api`)?" If the user says no, drop it — don't
   re-ask later in the same turn, and don't regenerate silently "to be safe."

5. **If yes, run it correctly.** The command is `npm run generate:api` inside
   `frontend/`, which runs `orval --config orval.config.js`. Two real
   gotchas, found the hard way (2026-08-24) while building this skill:
   - `orval.config.js` targets `${REACT_APP_API_BASE_URL}/openapi.json`,
     falling back to `http://localhost:8000/openapi.json`.
     `REACT_APP_API_BASE_URL` in `docker-compose.yml` is set to
     `http://localhost:8000` for the **browser's** benefit — that does not
     resolve from inside the `frontend` container. If running the command
     via `docker exec` against the frontend container, override it:
     `docker exec -e REACT_APP_API_BASE_URL=http://backend:8000
     aifluency-frontend-1 npm run generate:api`. If running on the host
     directly (not through the container), the default `localhost:8000`
     is correct as-is since the backend's port is published.
   - The backend must actually be running and reachable (`GET /health` on
     it) before generation — Orval needs to fetch the live schema, there's
     no cached fallback.

6. **After regenerating, remind — don't auto-commit.** Point out that the
   diff in `secureship.ts` is worth a skim before committing (new hook names,
   changed field types), consistent with this program's habit of reviewing
   AI output rather than accepting it blind. Do not `git add`/`git commit`
   the regenerated file yourself unless the user separately asks you to
   commit as part of this change.

## What this skill must never do

- Run `npm run generate:api` without an explicit yes to the question in
  step 4, even if the answer seems obvious.
- Silently skip suggesting because "it's probably not a breaking change" —
  let the user decide that; the whole point is surfacing the question, not
  filtering it.
- Touch any file other than running the one generation command — this skill
  doesn't hand-edit `secureship.ts` or hand-write a fetch call as a
  workaround if generation fails.
